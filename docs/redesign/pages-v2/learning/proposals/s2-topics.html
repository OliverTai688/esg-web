優點

  • 主線最直接：六個主題＝六片花瓣，點花瓣就換主題，選中的那片變橘色。
  • 掃讀層只有六個主題名與篇數；說明與文章標題一次只出現一組。
  • 六個面板都在 HTML 裡（未選的 hidden），搜尋引擎讀得到。
  • 花瓣位置固定，之後在文章頁、列表上用「第幾片亮起來」當主題標記。

風險

  • 花瓣最窄處手機約 61px：主題名只能四到五個字，長的兩個必須放在水平的兩片（已這樣排）。英文需要短名稱。
  • 花瓣以 60° 旋轉，超出文法的「90° 倍數」，需在整頁規劃中註明。
  • 手機上花在上、面板在下，點了花瓣要確認面板在視窗內。

與前後區塊的銜接

  • S1 → 本區：芽的兩片花瓣長成六片；捲入時花瓣由花心向外展開（靜止狀態就是開好的花）。
  • 本區 → S3：深色段以拱形上緣切入；被選中的橘色花瓣在下一區放大成托著精選文章的那一片。

優點

  • 每張卡直接帶一篇文章，少點一次。
  • 手機一次一張半，滑動是熟悉的手勢；卡片角落的花瓣與首頁合作單位卡同一個語彙。

風險

  • 桌機一次只看到三個主題，另外三個要按箭頭——六個主題不再是「一眼看完」。
  • 主題的一句說明放不進預算（六句共 222 字），只能整個拿掉。
  • 一張卡只能連到一個地方（主題頁或那篇文章），另一個入口就消失。
  • 花被拆成六張卡的角飾，「一朵花」不存在。

與前後區塊的銜接

  • S1 → 本區：芽的花瓣變成卡片角飾，尺寸變小、角色變弱。
