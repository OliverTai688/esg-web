## 二、一句話

**每個主題是一片花瓣；讀者每往下一段，花就多開一點。**
知識區在橋的有機端，主角形狀只有一個：黃色花瓣。`/learning` 把花瓣**繞著圓心**排（依主題），`/insights` 把同一批花瓣**沿著一條線**排（依時間）。兩頁用的是同一朵花，只是攤開的方式不同，所以一眼就分得出來，也看得出是同一批文章。

### 花瓣的固定角色（四個路由共用）

| 元素 | 意義 | 規則 |
|---|---|---|
| 六瓣花 | 六個主題 | 花瓣位置固定：右上起順時針＝創新策略、市場競爭力、永續責任、合作模式、溝通與換位思考、人物專訪。任何頁面上「第 N 片亮起來」都指同一個主題 |
| 花心（小圓） | 不屬於主題的內容（ESG共學坊公告） | 只亮花心 |
| 一片大花瓣 | 現在正在讀的那一篇／那一個主題 | 每屏最多一片 |
| 小花徽（24px 的六瓣花，其中一片是橘色） | 文章所屬主題的標記 | 取代原本六個不相干的線條 icon；永遠與主題名稱文字並排，不單靠形狀傳達 |

色彩：花瓣預設黃；「被選中／正在讀」換成橘；文字一律墨色（黃底、橘底都符合 AA）。冷灰只出現在深色段。

對形狀文法的一處延伸：六瓣花的花瓣以 60° 為單位繞圓心旋轉（文法原訂 90° 倍數）。理由與首頁 Hero「花瓣沿半圓展開」相同——這是「重組」而不是任意旋轉；花瓣本身的形狀、比例不變。除了花以外，其他地方的花瓣仍只用 90° 倍數與鏡射。

下拉選單第四項是離頁項目 `route: "/insights"`（最新文章），不出現在章節膠囊。**下拉 4 項＝3 個區塊＋1 個離頁項目**；章節膠囊 3 顆。

為什麼不是「一個主題一個區塊」：六個主題各自成段，頁面會多出六段結構相同的卡片牆（總字數更高），而且六段在手機上看起來仍然一樣。六個主題是「同一層級、互斥的內容」，依 `00` 第六節應該用分頁，不是長捲。所以六個主題收在一個區塊裡，由花瓣切換。

### 舊錨點

`#innovation`、`#market`、`#responsibility`、`#collaboration`、`#communication`、`#interviews` 仍被文章頁與主題頁的返回連結（`learningBackHref()`）以及站外連結使用。處理方式：六個 id 保留為 `#topics` 區塊頂端的定位點（不是 `<section>`，不算章節），抵達時頁面捲到「六大主題」並自動選好那一片花瓣。等於把 L01 的需求（返回要回到原本那個主題）做得更準：回去看到的就是那個主題的文章清單。

## 七、手機與桌機

- 六瓣花：桌機在右欄（最大 440px）、面板在左；手機花在上（滿欄寬，約 327px）、面板在下。花瓣是可點擊目標，最窄處也大於 60px；水平的兩片放最長的兩個主題名（市場競爭力、溝通與換位思考），斜的四片都是四個字。
- 篩選籤列：手機橫向滑動（容器內），每顆高 44px。
- 文章列：手機一欄 4 列、桌機兩欄 6 列，其餘在「顯示更多」之後。
- 跨界花瓣（交界 3、N1→N2）手機縮到 0.6 倍。
- 沒有 JavaScript 時：花瓣本身是連到主題列表頁的連結；所有文章標題都在 HTML 裡；月份列是原生 `<details>`。
