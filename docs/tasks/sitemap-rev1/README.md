## 一、結論先講

1. **客戶這份文件不只是改文案**。33 頁裡大約一半是文案替換，另一半包含：換整套品牌色、四個全新的內容區塊、時間軸重做、學習地圖，以及三項目前網站完全沒有的後端能力（聯絡表單寄信、email 名單、金流）。
2. **有三件事會卡住進度，而且都不在開發這一側**：
   - 素材：專案裡沒有任何圖片。logo、客戶商標、顧問照片、案例照片全在客戶的 Google Drive。
   - 客戶自己的新文案與自己訂的用語規則互相矛盾（多處仍寫「影響力白皮書」「共學坊」「媒合」）。
   - 金流與後端超出原需求書第一階段的範圍，需要先談範圍與費用。
3. **建議分五個階段**，第一階段只做不需要素材、不需要客戶回覆的項目，以件數計約佔全部任務的四成，可以最快讓客戶看到改變。

## 三、分階段開發建議

### Phase 0　確認與備料（立刻開始，與 Phase 1 同時進行）

目的是把會卡住後面階段的東西先解開。幾乎不寫程式。

- 把第五節的「待客戶確認清單」一次送給客戶，不要分批問。
- G07：取得 Drive 權限、下載並整理素材、確認授權。
- G02-A：依 CIS 規範做一版色彩方向示意，請客戶點頭。
- 與客戶對齊範圍：表單寄信、email 名單、金流是否另計（見第四節第 3 點）。

**完成的定義**：待確認清單都有回覆或明確的預設做法；素材狀態表每一列都有狀態；色彩方向確認。

### Phase 1　快速修正（不需素材、不需等回覆）

目的是最快讓客戶在線上版看到「你們提的我們改了」。全部是文案、資料、Bug，風險低。

建議順序：

1. **G01 用語統一**（先做且單獨做，它會掃過整份辭典）
2. G06 數字統一、E01 永續足跡 Hero

**完成的定義**：部署到預覽環境，客戶可逐頁對照 PDF 檢查；用語檢查指令通過。

### Phase 2　結構與新區塊（不需素材）

## 四、分析程式碼後的重要發現

這些會影響排程與報價，請先看。

1. **專案沒有任何圖片素材**。`public/` 只有腳手架預設的 5 個 svg，全站沒用到 `next/image`。Navbar 與 Footer 的 logo 是文字；生態圈的頭像是 GitHub 的假頭像，而且點了會連到 Google、Microsoft、UNICEF 的 GitHub 頁面。
2. **聯絡表單是空殼**。`/consulting` 的表單沒有送出邏輯，按下去只會重新整理頁面；另外有五處按鈕沒有任何連結。客戶要求把客服信箱改成 `pt@coesg.tw`，隱含的期待是表單會寄信到那裡，目前做不到。
3. **後端是零**。沒有 API、沒有環境變數、沒有寄信或資料庫套件。客戶提到的三件事（表單寄信、email 名單、改用我方金流）都需要新建基礎。原需求書（`docs/requirement-doc.md`）第一階段範圍是行銷頁面、語系切換、部署與 SEO，這三項應視為範圍外，需要另外談。
4. **首頁其實沒有「共好生態圈」區塊**。客戶在首頁段落貼的截圖來自 `/sustainability#ecosystem`，同一個區塊被標註了兩次。H5 與 S6 是同一個任務（S06）。
5. **同一組數字在辭典裡至少被複製了五份**，格式還不一樣（`~1000萬`、`1000萬`、`~1,000萬`）。這就是客戶覺得「數字一直重複」的來源。G06 收斂成一份。
6. **中英辭典結構綁定**。`en.ts` 的型別由 `zh.ts` 推導，任何結構變動都要同步寫英文，否則無法 build。客戶只給中文，所以每個任務都帶有暫譯成本，最後需要一次審校（X01）。
7. **`/consulting` 大部分文字寫死在程式裡**，英文版顯示的是中文。C01 會順手搬進辭典。
8. **換色不是改一個變數**。元件大多有用語意 token，但背景漸層、粒子、光束等十多處寫死綠色；而且橘色當主色時，「橘底白字」對比不足，需要重新分配深色面與強調色的角色（G02 有建議方案）。
9. **網域問題**。程式裡的正式網域寫的是 `https://coesg.tw`，但依時間軸文案與專案內的爬取資料推測，那目前是 ESG共學坊學習平台的網址，而客戶表示將停止與現行學習平台合作。新站要用哪個網域、舊平台內容如何處理，會影響 SEO 設定與上線計畫。
10. **Next.js 16 的注意事項**。`AGENTS.md` 要求寫碼前先查 `node_modules/next/dist/docs/`。已確認的一項：`src/middleware.ts` 是這個版本已棄用的寫法，應改為 `proxy`（T01）。

## 六、如何把任務交給 sub-agent 或多人並行

每個任務檔都寫成可獨立執行。交辦時給這樣一句就夠：

> 請依 `docs/tasks/sitemap-rev1/H02-home-brand-story.md` 實作，完成後跑 `pnpm lint` 與 `pnpm build`，回報改了哪些檔案與任何與任務檔不符的發現。

並行時要注意一個實際的衝突點：**幾乎每個任務都會改 `src/i18n/dictionaries/zh.ts` 與 `en.ts` 這兩個檔**，同時進行會一直合併衝突。兩種做法：

- **建議**：Phase 1 開頭先做一個小重構，把辭典依頁面拆檔（`dictionaries/zh/{common,home,sustainability,events,learning,consulting,join}.ts`，再組回同一個物件，型別不變）。之後依頁面分工就不會互相踩到。
- 不拆檔的話：G01 必須最先且單獨完成；之後一次只讓一個任務動同一頁的辭典區段，並用各自的 git worktree 隔離。

可以安全並行的分組（辭典拆檔後）：

| 並行線 | 任務 |
|---|---|
| 首頁 | H02、H03 → H01、H04 |
| 共好永續力 | S04 → S01 → S02 → S03 → S05 → S06 |
| 永續足跡 | E01 → E02 → E03 → E04 |
